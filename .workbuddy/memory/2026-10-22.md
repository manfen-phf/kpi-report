## 修复 P3「有效天数」误判（用户纠正了我的错误结论）

**用户反馈**：「这几个日期没有空值啊，SKU是否达标都有数据」

我上一轮说 10-08/10-14/10-15/10-17 这 4 天「数据没回填」——**用户是对的，我判断错了**。

### 根因：值类型不统一（不是空值！）

P3 的「SKU是否达标」列取值类型在不同日期不一样：
- 部分日是**字符串** `'1'` / `'0'`（1009、1013、1016、1018~1021）
- 部分日是**浮点数** `1.0` / `0.0`（1008、1014、1015、1017）

原判断：
```python
ok = (str(r[idx['SKU是否达标']]).strip() == '1')   # str(1.0)=='1.0' → 判负
```
→ 浮点型日达标数恒为 0 → 触发 `if sum(v[1]...)==0: continue` → 整天被跳过

### 修复
```python
ok = (_num(r[idx['SKU是否达标']]) == 1)   # _num 统一转 float
```
（`_num` 本来就在用，还能处理 #VALUE! 等坏值）

### 教训（重要）
1. **下「数据没回填」这类结论前必须先验证**。我看到「整列空」就下了结论，
   实际是「值类型不同」。**先 dump 该列的取值分布（用 repr 看类型）再判断**。
2. **数值列一律用 `_num()` 统一转换后比较**，不要 `str(x)=='1'`。
   同一报表不同日期的导出格式不一致是常态。
3. 货盘的 M/N 列（中文「达标」「攻克」）是文本值，字符串比较没问题，不受影响。

### 排查手法（可复用）
判断某天是否「有效」时，不要只看非空率，要看**值的分布**：
```python
vals = Counter(repr(r[ci]) for r in rows)
# ('1', 11209) ('0', 3400)      ← 正常
# ('1.0', 10454) ('0.0', 4155)  ← 类型不同，但数据完全正常
```
