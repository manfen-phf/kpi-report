## 二、日常更新（一键）

1. 把新一天的 Excel 放入上表对应目录（保持原命名规律）。
2. 双击 **`update.bat`**（整个流程约 3~4 分钟，其中取数占绝大部分）。
   - 调 `report_data.py` 重跑取数 → 重新生成 `data.js`
   - 调 `_deploy_api.py` 通过 GitHub API 提交并推送（单次运行只产生 1 个 commit）
   - Pages 通常 30~60 秒刷新生效

也可以只重跑取数看本地效果：

```bash
python report_data.py && start index.html
```

**鉴权**：`_deploy_api.py` 优先读环境变量 `GITHUB_TOKEN` / `GH_TOKEN`，其次读同目录 `.github_token` 文件，最后回落到本机 Git Credential Manager。**密钥不会提交进仓库**（`.gitignore` 已排除）。

> ⚠️ **`update.bat` 改动规范**（双击闪退的两个原因，务必遵守）
> 1. **行尾必须 CRLF** —— cmd.exe 解析 bat 依赖 CRLF，LF 会导致解析错乱直接闪退。
>    `.gitattributes` 已配 `*.bat text eol=crlf`，但**用工具重写文件后要显式转换**：
>    ```python
>    raw = open('update.bat','rb').read().replace(b'\r\n', b'\n').replace(b'\n', b'\r\n')
>    open('update.bat','wb').write(raw)
>    ```
> 2. **内容必须纯 ASCII** —— cmd 默认按 GBK 解析 bat，UTF-8 中文会变乱码，
>    甚至被当成命令执行（报「'文件' 不是内部或外部命令」）。
>    `chcp 65001` 只影响后续子进程输出，**救不了 bat 自身的编码**。中文提示请放 README，不要放 bat。

## 四、计分规则（10 月）

**① 结果指标 S1 拼好饭订单完成率（权重 40%）**
- 得分 = min(完成率, 120%) × 系数 × 40%
- 系数：≥80% = 1；< 80% = 0

**② 神抢手重点货盘达标率（权重 30%，东兰/凤山不考核）**
**③ 拼好饭重点货盘达标率（权重 20%，东兰/凤山 35%）**
- 得分 = 达标率 × 系数 × 权重
- 系数：70~100% = 1.2；60~70% = 0.8；< 60% = 0

**④ 结算价下探覆盖率（权重 10%，东兰/凤山 25%）**
- 得分 = 日均覆盖率 × 系数 × 权重
- 系数：60~100% = 1.2；50~60% = 1；30~50% = 0.8；< 30% = 0
- 日均覆盖率 = 考核期（10/8~10/31）各日 SKU 达标率的算术平均，**未发生日期取已发生最新日外推**

**过程指标**：满分 60 分，**罚款线 54 分（完成率 90%）**，60% 完成率 = 36 分。
完成率 ≥90% 直接免罚；唯一豁免 = 结果指标 ≥105% 且 过程指标 ≥60%。

**权重转移**：东兰县、凤山县无神抢手目标池，30% 转移给 ③（20%→35%）与 ④（10%→25%），过程权重合计仍 60%。

### 月末预估口径
- **① S1**：取近 5 个观测日的日均增量（增量按实际间隔天数折算，修正底表缺日造成的跳变）× 剩余天数，完成率封顶 135% 抑制小基数城市噪声
- **② 神抢手**：当前达标率 +（100% − 当前）× 10pp（按未达标部分 10% 达成估计），按 ②系数重算
- **③ 拼好饭**：沿用当前达标率（不外推）
- **④ P3**：沿用当前日均覆盖率（已按最新日外推至月底）

## 六、取数踩坑备忘（改脚本前先看）

1. **神抢手 GMV 取不到**：`⑥【商品绩效】` 的「高优池看板」神抢手交易额列（col22-27）在源表里是 `#VALUE!` 坏值，「自造神抢手底表」只有 20260511 单日陈旧数据。本报告暂不展示神抢手 GMV，若后续源表修复可在 `read_s1()` 旁补 `read_sqs_gmv()`。
2. **拼好饭-底表缺日**：底表并非每天都有行（历史缺 10/10），相邻相减会把跨 2 天增量当单日 → 增量必须按 `(b-a)/实际间隔天数` 折算。
3. **同星期滚动预估对小基数城市爆炸**：田东/东兰/凤山预估完成率会跑到 226%~10007% → 已废弃该算法，改用近 5 观测日日均增量线性外推 + 封顶 135%。
4. **P3 达标列未回填**：`1017` 文件「SKU是否达标」整列为 0，`read_p3()` 已加「整日达标数为 0 则跳过该文件」保护。目前仅 10/16、10/18 两天有效。
5. **P3 两套口径**：`3品类结算价下探` 汇总表基线（玉林 1385）远大于日文件（玉林 556），达标率低 10~20pp；已确认**采用 `2过程指标\结算价下探` 日文件**。
6. **分天节奏单日可超 200%**：东兰 189%、凤山 205%，属小基数城市正常波动。图表已封顶 150% 显示，并在下方列出实际值，避免拉爆 Y 轴。
7. **openpyxl 类型坑**：`isinstance(x, float)` 会漏掉被读成 int 的 100% 值 → 统一用 `(int, float)` 元组判断。
