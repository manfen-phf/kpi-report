# 商品运营分析报告（自动生成 · 每日更新 · 9月考核口径）

> ⚠️ **9月口径**：结果指标(40%) + 过程指标(60%) 四指标模型。旧 8月「拼好饭50%+货盘40%+覆盖10%」模型已废弃。

每天自动读取最新业务数据，生成「分区进度 / 玉林商进度」双板块可视化报告，并部署到 GitHub Pages 在线查看。

## 数据来源（自动读取最新文件）
- **结果指标（每日）**：`E:\0总商维度数据\KPI绩效\结果指标（每日）` —— 取数以表内 **G4 列日期**为准（文件名"X月Y日更"仅为更新日，非数据日）；提供 S1 PHF订单完成率。
- **过程指标（明细）**：`E:\0总商维度数据\KPI绩效\过程指标（明细）` —— 递归查找最新 `广西商品日报_明细汇总_去重_YYYY-MM-DD.xlsx`；按「来源」拆分神抢手/拼好饭，取「攻克情况=攻克」数 ÷ 目标数 得达标率。
- **覆盖率日维度**：`E:\0总商维度数据\KPI绩效\001重点货盘日报输出\商家参与优惠活动覆盖率\日维度数据` —— 提供 P3 商家参与优惠活动覆盖率。
- **9月目标/权重**：`E:\0总商维度数据\KPI绩效\考核目标\9月拼好饭神抢手绩效考核方案、目标.xlsx`（`sheet '0'`，实时读取，迭代无需改代码）。

## 日常更新（一键）
1. 把新一天的 Excel 放入上述对应目录（保持原命名规律）。
2. 双击 **`update.bat`**（或在本目录运行 `python generate_report.py`）。
3. 脚本会重新生成 `index.html`（最新）与 `商品运营分析报告-MMdd.html`（按日存档），并通过 GitHub API 部署到 GitHub Pages（无需 git push）。
   - 部署鉴权：自动读取本机 Git Credential Manager 中 github.com 的凭据；或设置环境变量 `GITHUB_TOKEN`。**密钥不会写入本仓库。**

## 计分规则（9月四指标）
- **结果指标 40%**：S1 PHF订单完成率。得分 = min(完成率,120%) × 系数 × 40% × 100；系数：完成率 <80%→0，≥80%→1。
- **过程指标 60%**（满分 72 = 60×1.2）：
  - P1 神抢手重点货盘商品达标率（权重 30%，东兰/凤山不考核）：系数 <50%→0，50–60%→0.8，≥60%→1.2。
  - P2 拼好饭重点货盘商品达标率（权重 20% / 东兰凤山 35%）：系数 <60%→0，60–70%→0.8，≥70%→1.2。
  - P3 商家参与优惠活动覆盖率（权重 10% / 东兰凤山 25%）：系数 <30%→0，30–50%→0.8，50–60%→1.0，≥60%→1.2。
  - 单项得分 = 达标率 × 系数 × 权重 × 100。
- **风险判定**：⚠️ 警告（总得分 < 90）｜ 💰 罚款（过程得分 < 54，即 72×0.9）｜ 🛡️ 可减免（结果≥42 且 过程≥43.2，即 72×0.6 时满足条件——是否实际免罚待规则确认）。
- **东兰/凤山**：无神抢手目标，权重转移到 拼好饭35% + 覆盖25%（过程合计仍 60%）。
